# KCK1002: Prefer SaveChangesAsync

> Available from 4.7.0, in the `Kck.Persistence.EntityFramework` package (ADR-0031).

| | |
|---|---|
| Severity | Info (shown as a suggestion in the editor, not in build output) |
| Category | `Kck.Persistence` |
| Code fix | No |

## Cause

A call to `DbContext.SaveChanges()` or `SaveChanges(bool)`. Calls to the base implementation inside an override of
`SaveChanges` are not reported.

## Why it matters

Kck dispatches domain events asynchronously after the save. A synchronous save blocks the calling thread while the
dispatch runs on a thread-pool thread, and a warning is logged each time (see
[Interceptors](../../providers/persistence.md#interceptors)).

## How to fix

Use `SaveChangesAsync` and pass the request's cancellation token:

```csharp
using Microsoft.EntityFrameworkCore;

public sealed class RenameOrderService(AppDbContext db)
{
    public async Task RenameAsync(Guid id, string email, CancellationToken ct)
    {
        var order = await db.Orders.SingleAsync(o => o.Id == id, ct);
        order.CustomerEmail = email;
        await db.SaveChangesAsync(ct);
    }
}
```

## When to suppress

Code that cannot be asynchronous (a synchronous library callback, a console tool without domain events) can turn the
suggestion off in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.KCK1002.severity = none
```
